# Benchmark Fixture Provenance

M14.4 defines the provenance metadata required when benchmark inputs or
comparator fixtures are generated, derived, or selected for benchmark evidence.
The governed machine-readable shape is `fixture_provenance` in
`benchmarks/inputs/manifest.schema.json`.

`fixture_provenance` records:

* `source_kind`: whether the input is an external dataset, synthetic fixture,
  derived fixture, materialized subset, or planned fixture.
* `source_description`: human-readable origin of the source.
* `source_uri`: source location when it can be recorded without leaking
  controlled data.
* `derived_from`: source ids, fixture ids, or manifest ids used to derive this
  input.
* `generation_command`: exact generation command, or an explicit statement
  that the input is a read-only external dataset not generated by Bamana.
* `generation_environment`: tool/container/storage context needed to reproduce
  the generation or selection step.
* `expected_semantic_scope`: the benchmark or comparator claim this input can
  support.
* `review_boundary`: claims this input must not be used to support.
* `checksum_policy`: how source and derived checksums are recorded before
  publication.
* `reproducibility_notes`: seed, fraction, mode, source id, or other details
  needed to regenerate derived inputs.

M14.4 is metadata-only. It does not materialize new benchmark fixtures, add
fixture generation scripts, add comparator claims, or change runtime benchmark
behavior. Later M14 tasks must provide command-specific generation scripts and
fixture checksums before new release-facing benchmark claims or comparator
claims are promoted.
